# rkk-guard —— 木马「疫苗 + 看门狗」

针对 `child.malware / ninel / pam_master / processhider` 这一族的**常驻免疫与自动清除**程序。
一个静态单文件，装上就能同时做到四件事：

| 功能 | 说明 |
|---|---|
| **免疫** | 在木马全部落点预置不可变占位，并锁死 `/etc/ld.so.preload`，让它**写不进来** |
| **实时回滚** | 每 2 秒巡检，木马改动过的配置**按最小范围改回**（不整文件覆盖，不冲掉你的正常改动） |
| **自动清除** | 一旦检测到病毒本体：先断持久化 → 再杀进程 → 再删文件 |
| **自愈** | 自身服务/二进制被删，几秒内自动恢复；被杀后 systemd 3 秒拉起 |

---

## 为什么它不会被木马"蒙住"

这匹木马的核心手段是把恶意库写进 `/etc/ld.so.preload`，于是机器上所有**动态链接**的程序
（`ls`、`ps`、`find`、`rm`、`kill`、`ss`、`last`…）都被劫持，看到的 `/proc`、目录、文件内容都是伪造的。

`rkk-guard` 是**全静态编译**（`CGO_ENABLED=0`），不经过 `ld.so`、不调用 libc，
杀进程/删文件走裸 syscall，所以它读到的现场是真实的、删除也是真的生效。

## 安装

```sh
# 1. 上传（x86_64 / ARM64 各一份）
scp rkk-guard-linux-amd64 root@目标IP:/root/rkk-guard
# 2. 装（会先体检，已中招就先清，然后布防 + 常驻 + 自愈）
chmod +x /root/rkk-guard && /root/rkk-guard install
# 3. 看状态
/root/rkk-guard status
```

安装时会打印计划并要求输入 `yes`；自动化场景加 `-yes`：

```sh
/root/rkk-guard install -yes              # 免确认
/root/rkk-guard install -yes -aggressive  # 同时清掉 node 账户
```

安装完的动作：

1. 体检 → 若中招，执行完整清除（自动备份到 `/var/lib/rkk-guard/backups/<时间>/`）
2. 布防 → 在 70+ 个落点建"不可变占位目录"，把 `/etc/ld.so.preload` 锁成不可变空文件
3. 安装 `/etc/systemd/system/rkk-guard.service`，`Restart=always`，`enable --now`
4. 二进制同时放 `/usr/local/sbin/rkk-guard` 与 `/usr/lib/rkk-guard/rkk-guard`（互备）

## 它到底怎么"免疫"

木马要落地，必然要在下面这些位置**创建文件**。`rkk-guard` 提前在这些路径放一个
**空目录 + `.rkk-vaccine` 标记 + `chattr +i`（不可变）**：

```
/var/lib/systemd/cache-service          /usr/local/lib/.system-service
/usr/local/lib/libnss_cache.so          /lib/security/pam_master.so
/lib/x86_64-linux-gnu/libnss_ninel.so.2 /etc/.pm
/usr/bin/ssshd                          /var/tmp/updates-20260202
/etc/cron.d/systemd-timers 等 3 个      /etc/initramfs-tools/hooks/zz-system-service
/etc/systemd/system/{systemd-resolved-cache,…} 共 12 个伪造 unit
/dev/shm/.orig_rm|.orig_kill|.orig_passwd|.orig_chattr
…以及其它伪装目录，共 76 处
```

效果：

- 木马 `open(path, O_CREAT)` → 拿到 `EISDIR`，**写不进去**；
- 想 `rm` 掉占位再写 → 目录带 `+i`，**连 root 都删不掉**（除非先 `chattr -i`）；
- 即使它先 `chattr -i` 再拆，守护 2 秒内会补回去（这段时间窗就是它唯一的可乘之机）。

同时把 `/etc/ld.so.preload` 设为**不可变空文件**——这是最致命的一环，锁住它，
木马就无法再劫持全系统的动态链接程序，`ps`/`ls` 也就不会再"说谎"。

> `rkk-guard` 自己会识别 `.rkk-vaccine` 标记，不会把自己的占位当成病毒误删（否则会陷入"删了建、建了删"的死循环）。
> 卸载时统一解除。

## 它怎么"改回去"

不是拿一份快照整文件覆盖（那样会冲掉你后来的正常配置），而是**只摘掉恶意的那一行/那一块**：

| 被改的地方 | 回滚方式 |
|---|---|
| `/etc/ld.so.preload` | 只删恶意行；若整文件都是恶意行则删除文件并重建为空（保持锁定） |
| `/etc/nsswitch.conf` | 只从 `passwd/shadow/group` 行里摘掉 `ninel`，其余行原样保留 |
| `/etc/pam.d/*` | 优先用木马自己的 `.pm-bak` 还原（**仅当备份本身干净**），否则按行删 `pam_master`；还原后重跑 `pam-auth-update` |
| `/etc/passwd|shadow|group|gshadow` | 只删 `ninel`（`-aggressive` 时连 `node`）那一行，不动其它账户 |
| `/etc/sudoers.d/*` | 删 `99-ninel-root`（`-aggressive` 时连 `node`），不用 `visudo` 覆盖 |
| `/etc/ssh/sshd_config` | 删 `Match User ninel` 块与 `StrictModes no`，保留你的 `Port`/`PermitRootLogin` 等设置 |
| `authorized_keys` | 按**公钥指纹** `SHA256:AkrAM6Cdbkqok1OHU527WzpYGQqPQJrubcEP9Dlj7yI` 精确删除，**你的 key 不动** |
| cron / crontab | 删恶意文件、按行摘掉 `system-service`/`876c7af6` 任务 |
| systemd unit / initramfs hook / rc.local / .bashrc | 停服务、删 unit、重建 initramfs、按行摘掉拉起命令 |
| 病毒本体 | 先杀进程（3 轮，防看门狗互拉）→ 再删文件，备份留 SHA-256 |

每一步都写日志：`/var/log/rkk-guard.log`（超过 5MB 自动轮转）。

## 命令一览

| 命令 | 作用 |
|---|---|
| `rkk-guard` | 只读扫描（发现则退出码 1） |
| `rkk-guard clean -yes [-aggressive]` | 清除一次，不常驻 |
| `rkk-guard install [-yes] [-aggressive]` | 安装守护（体检 → 布防 → 常驻 → 自愈） |
| `rkk-guard status` | 服务状态、布防点数量、`ld.so.preload` 锁定状态、最近 15 行日志 |
| `rkk-guard immunize` | 只布防，不装服务 |
| `rkk-guard patrol` | 手工触发一次巡检（调试用） |
| `rkk-guard uninstall` | 停服务、删 unit、**解除全部锁定**、删占位 |
| `RKK_ROOT=/mnt/disk rkk-guard …` | 对离线镜像操作（救援/取证） |

配置文件 `/etc/rkk-guard.conf`：

```ini
interval=2      # 巡检间隔秒（1–300），服务器吃紧可调 5
aggressive=0    # 1 = 连 node 账户一起清
```

## 已实测

在隔离环境构造了完整的模拟感染目录（30 个植入点），跑通了整套闭环：

| 测试 | 结果 |
|---|---|
| 布防后再扫描 | 76 处占位被正确识别为"自己人"，只报出 27–30 项真实病毒痕迹 |
| 第 1 次巡检 | 自动清除 37 项变更，**失败 0**，随后自动补防到 76 处 |
| 复检 | `未发现匹配特征。（已布防 76 处）` |
| 第 2 次巡检 | **无任何动作**（没有"删了建、建了删"的抖动） |
| 模拟黑客再次写入（加 `ninel`、投恶意 cron、丢回 40MB 载荷） | 下一次巡检全部改回：`passwd` 只剩 `root`，恶意 cron 与载荷消失 |
| 占位是否真的挡写入 | 向占位路径写文件 → `Is a directory`，写入被拒绝 |

## 必须知道的四个限制

1. **单机免疫，不是万能的**。对方若已拿到 root，可以 `chattr -i` 拆占位——守护会在 2 秒内补回，
   但**这 2 秒就是窗口**。要真正做到"打不进来"，还得从入口堵：关掉不必要的对外服务、
   修掉网站上的上传/命令执行漏洞、改掉所有弱口令。
2. **它会锁住 `/etc/ld.so.preload`**。你以后要手工改这个文件，必须先 `chattr -i /etc/ld.so.preload`，
   改完 `chattr +i` 回去；或者先 `rkk-guard uninstall`。
3. **不改业务数据**：不碰网站目录、数据库、用户文件；也不会自动重装 `rm/kill/chattr` 等被替换的命令
   （需要你执行 `apt-get install --reinstall -y coreutils passwd util-linux`，
   并且**绝不能用 `/dev/shm/.orig_*` 恢复**，那是木马的假副本）。
4. **它只能识别这一族**。root + PAM 万能密码 + initramfs 持久化意味着信任链已断：
   工具负责"止血 + 防复发"，**最终仍建议取证后重建系统**，只迁回网站文件与数据库。

## 卸载

```sh
rkk-guard uninstall
```

会停服务、删 unit、`chattr -i` 解除全部占位并删除、清理 `/usr/local/sbin/rkk-guard`。
备份（`/var/lib/rkk-guard/backups/`）与日志（`/var/log/rkk-guard.log`）保留，便于事后取证。

## 自己编译

```sh
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o rkk-guard-linux-amd64 .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w" -o rkk-guard-linux-arm64 .
```

源码三个文件：`main.go`（命令分发）、`guard.go`（免疫/巡检/自愈）、`core.go`（特征库与清除引擎），
纯 Go 标准库，无第三方依赖，可逐行审计。

> 仅用于自有或已获授权主机的安全防护。
