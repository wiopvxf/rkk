# 开源发布指南

## 一、发布前必须确认的三件事

1. **样本不进公开仓库**
   ```sh
   git status --short | grep samples
   ```
   如果 `samples/` 出现在待提交列表里，说明 `.gitignore` 没生效——检查文件名是否被
   `samples/*.zip` 规则覆盖，或执行 `git rm --cached -r samples/`。

2. **哈希可以公开，样本不能**
   `docs/IOC清单.txt`、`samples/SHA256SUMS.txt` 是分析师要的东西，保留；
   `samples/malware-sample.zip`（40MB 真实木马）只在私下传递。

3. **不要用 `git lfs` 托管样本**，很多平台对 LFS 内容同样会扫描封禁。

## 二、建仓

```sh
cd rkk-1.0.0
git init
git add .
git commit -m "rkk 1.0.0: immunize/monitor/auto-clean for the ninel rootkit family"
git branch -M main
git remote add origin git@github.com:<你的账号>/rkk.git
git push -u origin main
```

建议仓库设置：

- **Description**：`Immunize, monitor and auto-clean a Linux rootkit family (child.malware / ninel / pam_master)` 
- **Topics**：`linux` `security` `malware` `incident-response` `rootkit` `golang` `hids`
- **LICENSE**：MIT（已包含）
- **Security policy**：指向 `SECURITY.md`
- 关闭 Wiki，Issue 模板可选（提特征请附哈希与证据）

## 三、发布 Release

把 `dist/` 里的三个二进制作为附件上传（**不要**把 `samples/` 打进 Release assets）：

```sh
gh release create v1.0.0 \
  dist/rkk-linux-amd64 dist/rkk-linux-arm64 dist/rkk-linux-386 dist/SHA256SUMS \
  --title "rkk 1.0.0" \
  --notes "首个版本：30 项检测点、76 处免疫布点、2 秒巡检、自动清除与自愈。"
```

## 四、对外说明的口径

建议在 README 顶部保留"威胁模型与限制"一节，明确三点，避免被误解成"装上就万无一失"：

1. 单机免疫，2 秒窗口内仍可能被抢写；
2. 需要文件系统支持 `chattr +i`；
3. root + PAM + initramfs 被改，信任链已断，最终应重建。

同时说明**不采集任何遥测**：工具不联网、不上报、不收集主机信息（可审计，源码单文件）。

## 五、如果收到"样本请求"

统一回复：只提供哈希与 IOC，样本请自行通过 MalwareBazaar / VirusTotal 获取
（VT 上传会公开样本，提醒对方脱敏）。不要私下把 40MB 载荷转给陌生人，
一是扩散风险，二是你可能承担法律责任。
